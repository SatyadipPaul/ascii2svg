# Decisions

| Decision | Field | Score | Replaces | Why the old way was chosen | Overridden |
|---|---|---|---|---|---|
| Position against Mermaid by leading with "any text tree becomes a collapsible, linked diagram, no rewriting" (call trees, dependency trees, file trees, mind maps), then architecture path-highlighting. Not a new DSL. *Status: approved by the owner (goal set); built in 1.16.* | Product strategy | 7/10 (accept with fix list) | Positioning as "faithful 1:1 box diagrams for READMEs and LLM output" | The first goal was fixing and rendering diagrams that already exist (LLM output, READMEs) with a provable 1:1 result | no |
| Text as one `<text>` per word run with an x per character (default); `--portable` gives one per character; PNG frames always use one per character | SVG output | 8/10 | One `<text>` per character | Simplest exact 1:1 mapping, and every renderer places it right | no |
| Glow drawn with 7 layers instead of 14, same total density | SVG output | 8/10 | 14 layers | Smoothness; 7 is visually the same (checked by screenshot) | no |
| Still drawings write one `<path>` per line style (and fold group); animated ones keep a `<line>` per segment | SVG output | 9/10 | A `<line>` per segment always | Per-segment timing for animation | no |
| ASCII trees (`\|--` … `` `-- ``) are drawn as lines, only in the exact shape `tree` / `cargo tree` print | Parsing | 7/10 | `\|--` file trees always stay text | Fail-safe: when unsure, stay text. Kept: a strict shape rule, and markdown tables and look-alikes stay text (tested) | no |
| Folding is opt-in (`--interactive`, `--fold`, preset `explore`); the default SVG has no script | Interactivity | 8/10 | – (new) | Scripts don't run in `<img>` (GitHub), and some platforms strip them | no |
| Branch colours only on pure trees (no arrowheads anywhere); arrowed diagrams keep their colours | Styling | 8/10 | – (new) | Avoid restyling flowcharts such as the README's architecture diagram | no |
| A pasted tree (or a picked tree example) turns on Fold and Colour in the playground, with a note; typing, flowcharts and shared links are left alone | Playground UX | 8/10 | Ticking Fold by hand | Never change a reader's settings behind their back; a paste is one clear action and the note says what changed | no |
| Maven's one-dash branches `+- ` / `\- ` count as an ASCII tree, but only after `+` or `\`, never `\|-` | Parsing | 8/10 | Two dashes or more only | Fewer false trees; `\|- x` and `a +- b` still stay text, checked by tests | no |
| Engine speed-up with byte-identical output; `parse()` once, render many looks; design tokens, per-box links/tooltips and path highlighting; one-command docs setup. Native JS engine (dropping Pyodide) deferred until the engine settles. *Status: phases 1 and 2 built for 1.18. The speed target was cut from 3x/10x to the ~2x reached (owner chose option A) after profiling showed the rest spread over ten stages; phase 3 (docs command, --watch, Action) not started.* | Engine / product | 8/10 (accept with fix list) | Dict-of-cells grid scanned in full on each pass; whole pipeline re-run per look; look constants hard-coded | Simplest exact 1:1 mapping, and the diagrams were small | no |
| `highlight`: a named box lights its frame and its own words, not the boxes or lines inside it; only the stretches of line on a path between two named boxes light up (a box a line only passes through doesn't count; a frame crossing keeps the frame's and the line's states apart); a line's labels go with the line | Interactivity | 8/10 | – (new) | First versions lit everything inside a named box, then whole line networks with branches into dimmed boxes (found on the architecture diagram and by an independent review of decision-flow and C4) | no |
| Box links: http(s), mailto or relative only, escaped; work where the SVG is a page or `<object>`, not `<img>` | Security / SVG output | 9/10 | – (new) | `javascript:` / `data:` links in an SVG run script in the host page | no |
| Tokens tune colours, line width, font size and pulse timing; no cell-size token | SVG output | 8/10 | Hard-coded look constants | Cell size is shared by the parser's geometry, the self-check and the fold script; `--width` already scales the whole drawing | no |
| New options leave the default output byte-identical (every new attribute or CSS rule appears only when its option is used) | SVG output | 9/10 | – (new) | Users' committed SVGs and the website shouldn't change on upgrade | no |
